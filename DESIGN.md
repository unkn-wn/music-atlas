# Music Atlas: System Architecture & Implementation Specification
*The Living "Twitch Atlas" for the Global Streaming Music Landscape*

---

## 1. Executive Summary & Vision

### 1.1 Project Objective
**Music Atlas** is an interactive, GPU-accelerated 2D spatial network visualization that maps the global music ecosystem based on empirical streaming co-occurrence and playlist curation. Modeled after the iconic **Twitch Atlas** (which spatializes livestreamer communities through shared audience overlap), Music Atlas transforms millions of real-world playlist connections into a navigable, living cosmos of musical artists:

- **Constellations (Nodes):** 800+ dynamically harvested global artists, sized strictly proportional to verified Spotify Monthly Listeners / Followers, and color-coded by algorithmic genre communities.
- **Filaments & Bridges (Edges):** Curved inward Bézier chords connecting artists who share playlist placements, with stroke weight and opacity indicating mutual co-curation strength.
- **Continents & Archipelagos:** Organic topological landmasses generated by continuous force-directed physics (ForceAtlas2), grouping Pop, Hip-Hop, Latin / Reggaeton, Indie Rock, Classic Rock, EDM, and Bollywood into distinct, adjacent musical continents.
- **Honest Empirical Affinities:** In the artist inspector drawer, relationships are expressed directly as **Shared Playlists** (raw counts of co-curated streaming playlists worldwide) alongside normalized affinity bars, strictly capped to the top 10 most relevant connections.
- **Audio Discovery:** Instant 30-second streaming audio previews powered by direct Spotify MP3 CDN streams, Deezer previews, and Apple iTunes integration.

## 2. The Strict Zero-Hardcoding Mandate

Earlier iterations of Music Atlas relied on static, hardcoded artist catalogs and synthetic playlist generation. While useful for rapid prototyping, this introduced fatal flaws:
1. **Selection Bias:** Hand-curated lists favor developer tastes and miss explosive breakthroughs (e.g. regional corridos, Afrobeats, Latin trap).
2. **Artificial Topography:** Synthetic co-occurrences cluster artists by presumed genre labels rather than real human listening behavior.
3. **Stale Metrics:** Hardcoded follower counts diverge from streaming reality.

**Architectural Principle: All data is 100% empirical.**
- Every artist is ingested dynamically from live global streaming charts.
- Every monthly listener metric is the exact daily ground truth.
- Every connection represents verified co-placement on public playlists.
- Zero synthetic seeding, zero hardcoded fallback spokes.

## 3. Data Sourcing & Multi-Vector Harvester

To capture the global music landscape without relying on deprecated APIs or paid enterprise subscriptions, Music Atlas employs a **Multi-Vector Public Harvester**:

```
+-------------------------------------------------------------------------------+
|                      MULTI-VECTOR PUBLIC HARVESTING LAYER                     |
+-------------------------------------------------------------------------------+
|                                                                               |
|  [Kworb Spotify Daily Listeners]            [Apple iTunes Search API]         |
|   - Scrapes daily table of 2,500 artists     - Resolves canonical taxonomy    |
|   - Exact monthly listeners & 22-char IDs    - Maps 1000+ genres to 11 sectors|
|   - Logarithmic popularity scoring           - Persistent disk caching        |
|                 \                                   /                         |
|                  +-----------------+----------------+                         |
|                                    v                                          |
|                     [Dynamic Catalog Universe]                                |
|                                    |                                          |
|       +----------------------------+----------------------------+             |
|       |                            |                            |             |
|       v                            v                            v             |
|  [Vector A: Spotify Embeds]  [Vector B: YouTube Music]    [Vector C & D: Kworb|
|   - 80+ flagship editorial    - 70+ genre & regional       & Apple Music RSS] |
|     embeds via Next.js JSON     community playlists       - 72 country daily  |
|   - Tracklists + 30s MP3s     - Cached incrementally        charts + 25 RSS   |
+------------------------------------+------------------------------------------+
```

### 3.1 Artist Catalog & Genre Taxonomy (`pipeline/00_harvest_artists.py`)
1. **Kworb Spotify Daily Listeners Index**: Scrapes `https://kworb.net/spotify/listeners.html`, extracting the top 2,500 artists globally with their canonical 22-character Spotify ID and verified monthly listener counts.
2. **Logarithmic Popularity**: Streaming listenership follows a power law. Popularity is computed empirically:
   $$P = \min\left(100, \max\left(20, \text{round}\left(20 + 80 \cdot \frac{\log_{10}(L) - 6.0}{8.2 - 6.0}\right)\right)\right)$$
   Where $L$ is daily monthly listeners (e.g. 1M listeners $\to 20$, 130M listeners $\to 97$).
3. **Genre Taxonomy via Apple iTunes**: Every artist is resolved via `https://itunes.apple.com/search?term={name}&entity=musicArtist&limit=1`. Primary genre strings and subgenre tags are cached on disk (`itunes_genre_cache.json`) and classified into 11 canonical continental sectors:
   - Pop
   - Hip-Hop / Rap
   - Indie / Alternative
   - EDM / Electronic
   - Latin / Reggaeton
   - R&B / Soul
   - Rock / Metal
   - Country / Folk
   - K-Pop
   - Afrobeats / Dancehall
   - Jazz / Classical
4. **Soft-Quota Allocation**: Enforces balanced macro-genre distribution with automatic soft-quota rollover for exhausted niche genres.

### 3.2 Multi-Vector Playlist Crawling (`pipeline/01_data_source.py`)
- **Vector A (Spotify Public Embeds):** Ingests 81 flagship editorial playlists (Today's Top Hits, RapCaviar, Viva Latino, Hot Country, Rock Classics, etc.) by extracting `__NEXT_DATA__` JSON from `https://open.spotify.com/embed/playlist/{id}`. Extracts official 30-second MP3 audio preview URLs (`audioPreview.url`) and tracklists without requiring Spotify OAuth.
- **Vector B (YouTube Music Community Playlists):** Uses unauthenticated `ytmusicapi` across 70+ diverse queries covering all 11 genres, regional scenes (Bollywood, Punjabi, Sertanejo, Corridos, K-Pop, J-Pop, Afrobeats, Amapiano, Drill, Metal, Indie), caching 550+ public playlists incrementally.
- **Vector C (Kworb Spotify Country Charts):** Crawls daily Top 200 rankings across 72 countries, capturing national listening patterns.
- **Vector D (Apple Music Most-Played RSS):** Ingests top tracks from 25 international storefronts.

### 3.3 Text Normalization & Collaboration Tokenization
- Multi-artist tracks are normalized with Unicode NFKD decomposition, stripped of diacritics, lowercased, and split on collaboration delimiters:
  ` feat. `, ` ft. `, ` featuring `, ` & `, ` and `, ` with `, ` x `, ` / `, `, `
- Strings are matched first against the catalog by 22-character Spotify ID, then by normalized artist name.

### 3.4 Iterative Convergence Safeguard
- An artist is retained only if they meet two strict connectivity criteria under iterative $k$-core convergence:
  1. $\ge 2$ appearances across harvested playlists.
  2. $\ge 4$ distinct catalog peers co-occurring in the same playlists.
- Playlists containing fewer than 2 surviving catalog artists are pruned, guaranteeing that every entry in the affiliation matrix contributes to valid topological structure.

## 4. Mathematical Graph Modeling & Sparsification

```
[Harvested Bipartite Pairs]
           |
           v
[CSR Sparse Affiliation Matrix M] ---> [Co-Occurrence Projection C = M^T * M]
                                                   |
                                                   v
[Salton's Cosine Normalization] <------------------+
s_ij = c_ij / sqrt(c_i * c_j)
           |
           v
[Evidence-Scaled Degree Bounds]
d_max(i) = min(28, max(4, floor(sqrt(c_i) * 4.5)))
           |
           v
[Mutual k-NN & High-Affinity Admission]
(Mutual in Top-k) OR (c_ij >= 4) OR (c_ij >= 2 and sim >= 0.15)
           |
           v
[Iterative k-Core Pruning & Single Giant Component Guarantee]
           |
           v
[Positive Layout Attraction Floor: 0.15 .. 1.0]
```

### 4.1 Bipartite CSR Matrix Projection (`pipeline/02_build_cooccurrence.py`)
The affiliation pairs are represented as a binary Compressed Sparse Row (CSR) matrix $M \in \mathbb{R}^{P \times A}$, where $P$ is playlists and $A$ is artists.
The pairwise co-occurrence matrix $C \in \mathbb{R}^{A \times A}$ is computed via sparse matrix multiplication:
$$C = M^T M$$
- Diagonal elements $C_{ii} = c_i$ represent the marginal playlist frequency of artist $i$.
- Off-diagonal elements $C_{ij} = c_{ij}$ represent the number of shared playlists between artist $i$ and artist $j$.

### 4.2 Salton's Cosine Similarity (`pipeline/03_normalize_and_sparsify.py`)
Raw co-occurrence counts favor ubiquitous mega-artists who appear everywhere. To measure true affinity, raw counts are normalized using **Salton's Cosine**:
$$s_{ij} = \frac{c_{ij}}{\sqrt{c_i \cdot c_j}}$$
This bounds similarity to $[0.0, 1.0]$ and ensures that niche artists sharing 3 out of 3 playlists have higher topological affinity than two mega-stars who share 4 out of 100 playlists.

### 4.3 Evidence-Scaled Degree Bounds
To prevent low-sample artists from accumulating dozens of spurious edges from a single large playlist (e.g. Hanumankind appearing on one 40-track playlist), an artist's maximum degree is dynamically bounded by their streaming evidence:
$$d_{\max}(i) = \min\left(28, \max\left(4, \left\lfloor \sqrt{c_i} \cdot 4.5 \right\rfloor\right)\right)$$
- An artist with $c_i = 3$ is capped at $4 - 7$ connections.
- An artist with $c_i = 10$ is capped at $14$ connections.
- Global superstars ($c_i \ge 50$) can form up to $28$ rich connections.

### 4.4 Global Candidate Admission
Candidate pairs are sorted globally by raw shared playlists first, then cosine similarity. An edge $(i, j)$ is admitted if:
1. Both artists mutually consider each other in their top $k$ candidates (`k_local = 12, k_bridge = 8`), OR
2. Strong empirical evidence exists: $c_{ij} \ge 4$ shared playlists, OR $c_{ij} \ge 2$ with $s_{ij} \ge 0.15$.
3. Neither node has exceeded its evidence-scaled degree bound.

### 4.5 Single Giant Connected Component Invariant
1. Component bridging identifies secondary subgraphs and links them to the giant component using the highest-scoring candidate pair with $c_{ij} \ge 1$.
2. Iterative $k$-core pruning removes any nodes falling below minimum degree ($d < 4$).
3. Post-pruning connectivity check via `scipy.sparse.csgraph.connected_components` verifies that $100\%$ of surviving nodes belong to a single, unified connected component. Any disconnected secondary fragments are pruned.

### 4.6 Positive Layout Attraction Floor
Min-max rescaling cosine similarities to $[0.0, 1.0]$ causes the weakest edges to receive weight $0.0$, producing zero attraction in ForceAtlas2 ($F_{\text{att}} \propto \text{weight} \cdot d$).
Edge weights are mapped to enforce a strictly positive layout attraction floor:
$$w_{\text{norm}} = 0.15 + 0.85 \cdot \frac{s_{ij} - s_{\min}}{s_{\max} - s_{\min}}$$
Every connected edge exerts at least $15\%$ baseline inward spring tension, preventing peripheral nodes from being flung into outer space by repulsive forces.

## 5. Raw Apple iTunes API Genre Grouping (`pipeline/04_community_detection.py`)

To eliminate heuristic bias, arbitrary manual continent definitions, and synthetic TF-IDF compound names, Music Atlas groups artists **strictly by their raw official Apple iTunes API genre output**:

1. **Direct Raw Output:** Every catalog artist's genre is queried directly against the Apple iTunes Search API (`itunes.apple.com/search?term={name}&entity=musicArtist&limit=1`). The resulting `primaryGenreName` string (e.g. `Hip-Hop/Rap`, `Pop`, `Alternative`, `Rock`, `Country`, `R&B/Soul`, `K-Pop`, `Latin`, `Dance`, `Soundtrack`, etc.) is used directly without normalization or dictionary mapping.
2. **Zero Synthetic Quotas & Zero Hardcoded Continents:** Hardcoded catalog dictionaries and synthetic quota enforcements are completely removed. All artist genre assignments reflect empirical ground truth.
3. **Perceptual Color Palette:** Each unique raw genre is assigned a distinctive, high-contrast color from a vibrant palette.

## 6. Natural Two-Phase ForceAtlas2 Layout Physics (`pipeline/05_layout_forceatlas2.py`)

Layout spatialization translates graph topology into an organic, continuous cosmic web matching the original topography from commit `691cd95`:

### 6.1 Two-Phase Simulation
- **Stage 1 (LinLog Macro Spreading):**
  - `linLogMode = True`: LinLog attraction clusters tightly-connected musical communities while allowing distant genres to form an organic archipelago topography with natural bays and straits.
  - `scalingRatio = 6.5`, `gravity = 0.35`, `edgeWeightInfluence = 1.0`, `strongGravityMode = False`.
- **Stage 2 (Local Refinement & Anti-Collision):**
  - `linLogMode = False`, `adjustSizes = True`: Accounts for physical node footprints to eliminate overlaps among high-degree headliners.
  - `scalingRatio = 24.0`, `gravity = 0.15`, `edgeWeightInfluence = 0.6`.
- **Stage 3 (Pairwise Spacing Relaxation):**
  - Iterative distance relaxation with `min_dist = 28.0px` ensures clean breathing room between neighboring artists.
  - Coordinates normalized to expanded galactic canvas `[-1350.0, 1350.0]`.
- **Zero Circular Constraints:** No circular harmonic angle seeding, no artificial radial jitter, and no `strongGravityMode` spherical forcing.

## 7. Metadata Hydration & Previews (`pipeline/06_hydrate_metadata.py`)

Every artist is enriched with high-resolution artwork and a playable 30-second audio preview through a 3-tier fallback chain:
1. **Tier 1 (Spotify Embed MP3):** Captured directly from Spotify CDN during Step 1 embed scraping (zero auth, 100% official 30s preview).
2. **Tier 2 (Deezer API):** Queried via `https://api.deezer.com/artist/{name}/top?limit=5` (open MP3 stream + 500x500 portrait image).
3. **Tier 3 (Apple iTunes Search API):** Fallback via `https://itunes.apple.com/search?term={name}&entity=song&limit=1` (256kbps AAC/M4A preview stream).
All results are cached on disk (`artist_metadata_cache.json`) to prevent redundant network requests.

## 8. Web Artifact Bundling & Frontend Architecture

### 8.1 Compact Artifact Export (`pipeline/07_export_web_artifacts.py`)
Exports `web/public/data/atlas-graph.json` using compact serialization (`separators=(',', ':')`), reducing bundle size from 13.6 MB to ~3.8 MB.
- Prunes dangling edges (edges referencing unpositioned or missing nodes).
- Injects inward radial Bézier curvature into edges for an organic spiderweb filament aesthetic.
- Exports top 10 related artists sorted by shared playlists and cosine similarity.

### 8.2 WebGL Sigma.js Rendering (`web/src/components/AtlasCanvas.tsx`)
- Renders 800+ nodes and 5,000+ edges at 60/120 FPS using WebGL shaders.
- **Node Sizing:** Proportional to square-root followers:
  $$\text{size} = 2.5\text{px} + 25.5\text{px} \cdot \frac{\sqrt{F} - \sqrt{F_{\min}}}{\sqrt{F_{\max}} - \sqrt{F_{\min}}}$$
  (Slightly scaled between 2.5px for emerging artists and 28.0px for global superstars).
- **Headliner Avatars:** Top 5% artists by listenership display high-resolution circular portrait imagery at macro zoom levels.
- **Focus Mode & 1-to-1 Parity:** Clicking an artist dims the rest of the cosmos and illuminates ONLY the exact top 10 edges that correspond to the related artists listed in the inspector drawer. This eliminates visual noise and guarantees strict 1-to-1 parity between the visual canvas and the sidebar.

### 8.3 Artist Inspector Drawer (`web/src/components/ArtistDrawer.tsx`)
- High-resolution portrait banner with ambient backdrop blur.
- Verified Monthly Listeners formatted cleanly (e.g. `133.2M`).
- Instant 30-second playable streaming preview.
- **Top Related Artists (Top 10):**
  - Displays raw **Shared Playlists** (e.g. `63 shared playlists`, `2 shared playlists`), accurately reflecting real co-curation without misleading audience percentage claims.
  - Relative affinity progress bars scaled to the artist's #1 top connection.
  - Interactive click-through: clicking any neighbor smoothly flies the camera to that artist.
- World Radar minimap is removed completely for immersive full-canvas exploration.
