# Music Atlas: System Architecture & Implementation Specification
*The "Twitch Atlas" for the Global Music Ecosystem*

---

## 1. Executive Summary & Vision

### 1.1 Project Objective
**Music Atlas** is an interactive, GPU-accelerated 2D spatial network visualization that maps the global music landscape based on real-world listener co-occurrence and playlist curation. Modeled after the iconic **Twitch Atlas** (which spatializes streamer communities via shared viewer overlap), Music Atlas transforms millions of playlist connections into a navigable, living cosmos of musical artists:
- **Nodes (Artists):** Represented as circles, sized by popularity / monthly listener scale, and colored by genre community.
- **Edges (Crossover):** Lines connecting artists who share listeners/playlists, with line thickness indicating crossover volume.
- **Edge Thresholding:** Real-time user-controlled slider filtering out faint crossover noise and revealing strong musical bridges.
- **Continents & Archipelagos:** Organic geographical landmasses generated by force-directed physics (ForceAtlas2), grouping Hip-Hop, Indie Rock, EDM, Metal, K-Pop, Latin, and Pop into intuitive clusters.
- **Rich Interaction:** 60/120 FPS camera pan/zoom, fuzzy search with smooth fly-to animations, neighborhood illumination on hover, artist inspector cards, and instant 30-second audio previews.

```

## 3. Data Sourcing & API Reality Check

### 3.1 Spotify API Constraints (Post-November 2024 Deprecations)
On **November 27, 2024**, Spotify implemented major breaking changes across the Web API:
1. `GET /v1/artists/{id}/related-artists` is **deprecated** and returns `403 Forbidden` for all new applications.
2. `GET /v1/recommendations`, `audio-features`, and `audio-analysis` are **deprecated**.
3. `preview_url` (30-second MP3 preview) on track objects returns `null` or is restricted.
4. Spotify Web Playback SDK strictly requires user authentication (OAuth) and an active **Spotify Premium subscription**.
5. Spotify `/v1/search` enforces a hard limit of `offset + limit <= 1000`, making bulk playlist scraping via search impossible.

### 3.2 Dual-Source Data Architecture
To overcome these API boundaries, Music Atlas combines offline open datasets with targeted, compliant API hydration:

```

+-------------------------------------------------------------------------------+
|                                                                               |
|  [Spotify Million Playlist Dataset (MPD)]       [ListenBrainz User Scrobbles] |
|   - 1,000,000 user playlists                     - Open scrobble dumps        |
|   - 2,000,000+ unique tracks                     - Real user listening logs   |
|   - 300,000 artists                              - Complementary validation   |
|                 \                                       /                     |
|                  +------------------+------------------+                      |
|                                     |                                         |
|                                     v                                         |
|                  [Bipartite Projection & Sparse Matrix]                       |
|                                     |                                         |
|                                     v                                         |
|                    [Top 10,000 Artists Universe]                              |
|                                     |                                         |
|                 +-------------------+-------------------+                     |
|                 |                                       |                     |
|                 v                                       v                     |
|    [Spotify Web API (Client Creds)]       [Deezer / iTunes Search API]        |
|     - Hydrate top 10k artists              - Enrich top tracks with open      |
|     - Batch GET /v1/artists?ids=...          30s MP3 preview audio URLs       |
|     - Popularity, images, genres           - Zero auth, no login required     |

1. **Co-occurrence Source:** Spotify Million Playlist Dataset (MPD) provides 1,000,000 real-world playlists. A user adding Artist $A$ and Artist $B$ to the same playlist represents an explicit co-curation vote.
2. **Metadata Hydration:** Spotify Web API (`GET /v1/artists?ids=...`) accepts up to 50 IDs per request. Hydrating 10,000 artists requires exactly **200 requests**, taking $<10$ seconds under standard rate limits.
3. **Audio Previews:** Deezer API (`https://api.deezer.com/artist/{name}/top?limit=5`) and iTunes Search API (`https://itunes.apple.com/search?term={name}&entity=song`) provide reliable, open 30-second MP3 streams requiring no authentication or subscription.
4. **Interactive Playback:** Official Spotify IFrame API (`https://open.spotify.com/embed/artist/{id}`) embedded in the artist inspector drawer for full track/album streaming for logged-in Spotify users.

## 4. Mathematical Graph Pipeline & Topology

### 4.1 Inverted Execution Order (Preventing OOM)
Generating co-occurrences by joining 1,000,000 playlists across 300,000 artists in a relational database produces an intermediate table of **750M to 1.2B rows**, causing out-of-memory (OOM) crashes.

**Solution:** Invert the pipeline order using compressed sparse linear algebra:
1. **Frequency Pass:** Scan playlists linearly once to compute marginal frequency count $C_i$ for each artist across all playlists.
2. **Universe Pruning:** Select the Top $N = 10,000$ artists based on overall frequency and catalog prominence.
3. **Filtered Projection:** Filter playlists to only retain tracks by the Top $N$ artists (dropping average unique artists per playlist from $\sim40$ to $\sim15$, reducing combinatorial expansion by $>85\%$).
4. **Sparse Matrix Representation:** Map artists to sequential integer indices $[0, N-1]$. Build a binary Compressed Sparse Row (CSR) matrix:
   $$M \in \{0, 1\}^{P \times N}$$
   where $M_{p, i} = 1$ if playlist $p$ contains artist $i$, and $0$ otherwise.
5. **Sparse Matrix Multiplication:**
   $$C = M^T M$$
   The resulting symmetric matrix $C \in \mathbb{N}^{N \times N}$ contains exact co-occurrence counts:
   - Diagonal $C_{ii}$ = total playlists containing artist $i$.
   - Off-diagonal $C_{ij}$ = total playlists containing both artist $i$ and artist $j$.
   *Runtime in SciPy:* $< 15$ seconds, peak RAM $< 1.2$ GB.

### 4.2 Edge Normalization: Salton's Cosine with Co-occurrence Floor
Raw co-occurrence heavily biases superstars (e.g., Drake or Taylor Swift appearing in thousands of unrelated playlists). 

We evaluate four normalization metrics:
- **Jaccard Similarity:** $J(A, B) = \frac{C_{ab}}{C_a + C_b - C_{ab}}$ (Over-penalizes pairs when $C_a \gg C_b$, cutting megastars from their legitimate sub-genre peers).
- **Szymkiewicz-Simpson Overlap:** $O(A, B) = \frac{C_{ab}}{\min(C_a, C_b)}$ (Floods the graph with false shortcut edges from micro-artists into superstars).
- **Unsmoothed PPMI:** $\max(0, \log_2 \frac{P(A, B)}{P(A)P(B)})$ (Suffers from extreme low-frequency amplification).
- **Salton's Cosine Similarity (Chosen Metric):**
  $$S_C(A, B) = \frac{C_{ab}}{\sqrt{C_a \cdot C_b}} \quad \text{for } C_{ab} \ge C_{\min}$$

**Selected Standard:**
- **Co-occurrence Floor:** $C_{ab} \ge 10$ shared playlists (eliminates random noise).
- **Edge Weight ($w_{ab}$):** Salton's Cosine Similarity $S_C(A, B) \in [0, 1]$.
- **Display Metric (UI Inspector):** Directional audience overlap:
  $$\text{Crossover}(A \to B) = \frac{C_{ab}}{C_a} \times 100\% \quad \text{("82% of Artist A listeners also listen to Artist B")}$$

### 4.3 Graph Sparsification & Hairball Elimination
A full graph of 10,000 artists contains up to $50$ million potential edges. Feeding an unpruned network into ForceAtlas2 creates a dense, illegible "hairball".

We apply a two-tier sparsification strategy:
1. **Mutual k-Nearest Neighbors (m-kNN):** For each artist $A$, rank all neighbors by cosine similarity $S_C(A, B)$. Keep an undirected edge if and only if both artists are mutually in each other's top-k:
   $$(A, B) \in E \iff B \in \text{top-}k(A) \land A \in \text{top-}k(B) \quad (k = 20)$$
2. **Degree Clamp & Backbone Preservation:**
   - To accommodate bridge artists without creating hubs, allow asymmetric edges if $S_C(A, B) \ge 0.25$, but strictly clamp maximum node degree: $k_{\max} \le 30$.
   - Run **Serrano's Disparity Filter** ($\alpha = 0.05$) to preserve multiscale cluster backbones across both high-density pop hubs and sparse underground genres.
3. **Final Graph Scale:**
   - Nodes: $10,000$ artists.
   - Edges: $\sim 70,000$ to $90,000$ high-signal edges.
   - Average degree: $\sim 14$ to $18$ connections per artist.

## 5. Community Detection & Perceptual Color Hierarchy

### 5.1 Leiden Modularity Clustering
Rather than relying on Spotify's inconsistent micro-genres (which are missing for up to 15% of catalog artists and cause a speckled "confetti" visual artifact), **colors are anchored directly to the graph's topological communities**:
1. Run the **Leiden Algorithm** (modularity optimization with resolution $\gamma = 1.0$) directly on the sparsified, weighted co-occurrence graph.
2. The algorithm partitions the 10,000 artists into $12$ to $16$ robust macro-communities representing natural musical continents (e.g., Hip-Hop/Trap, Indie/Alternative, EDM/House, Latin/Reggaeton, Metal/Hard Rock, K-Pop, Country/Americana).
3. Within each macro-community, perform a second-level Leiden partition ($\gamma = 1.8$) to identify $3$ to $6$ micro-communities (e.g., within Electronic: Techno, House, Drum & Bass, Dubstep).

### 5.2 Consensus Genre Labeling (TF-IDF)
For each detected community $C_k$, aggregate all constituent artists' Spotify genre tags and compute TF-IDF scores:
$$\text{TF-IDF}(g, C_k) = \frac{\text{count}(g, C_k)}{\sum_{g' \in C_k} \text{count}(g', C_k)} \times \log \frac{|C|}{\sum_{C_j} \mathbb{I}(g \in C_j)}$$
The top 3 scoring genres become the official human-readable label for that continent (e.g., `Community 3` $\to$ **"Hip-Hop / Southern Trap / Melodic Rap"**).

### 5.3 Oklab Perceptual Color Palette
To ensure maximum visual distinctiveness, accessibility, and aesthetic elegance:
- Macro-communities receive distinct hues evenly distributed across the **Oklab color space**:
  - Hip-Hop / Rap: Deep Amber / Orange (`#F59E0B`)
  - Pop: Vibrant Hot Pink (`#EC4899`)
  - Indie / Alternative: Sage Green (`#10B981`)
  - EDM / Electronic: Cyan / Electric Blue (`#06B6D4`)
  - Rock / Metal: Crimson / Ruby (`#EF4444`)
  - R&B / Soul: Purple / Violet (`#8B5CF6`)
  - Latin / Reggaeton: Golden Yellow (`#EAB308`)
  - Country / Americana: Warm Ochre (`#D97706`)
  - K-Pop / J-Pop: Neon Magenta (`#F43F5E`)
  - Jazz / Blues: Deep Indigo (`#6366F1`)
  - Classical / Ambient: Slate Teal (`#14B8A6`)
- Sub-communities vary in **lightness ($L$) and chroma ($C$)** within the macro-hue, creating clear sub-regions within each continent.

## 6. Spatial Physics Engine (ForceAtlas2)

### 6.1 Two-Phase Annealing & Collision Resolution
Running ForceAtlas2 with incorrect Barnes-Hut parameters ($\theta > 1.0$) or early collision adjustment (`adjust_sizes = True`) causes force explosion ($NaN$ coordinates) and quadtree grid artifacts.

**Stable Two-Phase Simulation Architecture:**
```
+-----------------------------------------------------------------------------------+
|                           FORCEATLAS2 SIMULATION PIPELINE                         |
+-----------------------------------------------------------------------------------+
|  Largest Connected Component (LCC) Extraction (>98% of nodes)                     |
|  Initial Node Placement: Spectral Graph Embedding (Laplacian Eigenmaps)           |
|                                                                                   |
|  [PHASE 1: Macro-Continent Formation] (Iterations 1 - 1,600)                     |
|    - Barnes-Hut theta: 0.6 (Strict multipole acceptance criterion)                |
|    - LinLog Mode: ENABLED (Logarithmic attraction Fa = log(1+d) pulls            |
|      densely linked clusters tight, pushing distant continents apart)             |
|    - adjust_sizes: FALSE (Prevents division-by-zero explosions on overlap)        |
|    - Gravity: 0.8 (Keeps peripheral nodes from drifting)                          |
|    - Scaling Ratio: 12.0                                                          |
|    - Temperature: Exponential decay from T_max to T_min                           |
|                                                                                   |
|  [PHASE 2: Anti-Collision & Micro-Spacing] (Iterations 1,601 - 2,000)             |
|    - adjust_sizes: TRUE (Account for node radii based on popularity)              |
|    - LinLog Mode: DISABLED (Linear attraction stabilizes fine positioning)        |
|    - Step Size: Low constant step size (0.1)                                      |
|    - Voronoi / Noverlap relaxation pass to guarantee zero label collision         |
|                                                                                   |
|  [POST-PROCESSING]                                                                |
|    - Bounding-Box Packing: Position secondary disconnected components into         |
|      neat peripheral archipelagos                                                 |
|    - Normalization: Rescale coordinates (x, y) into range [-1000.0, 1000.0]       |
+-----------------------------------------------------------------------------------+
```

## 7. Frontend WebGL Architecture (Sigma.js v2 + Graphology)

### 7.1 Tech Stack Decision: Sigma.js v2 vs. Cosmograph

| Feature | Cosmograph | Sigma.js v2 + Graphology (Selected) |
| :--- | :--- | :--- |
| **Rendering** | WebGL / WebGPU | WebGL 2.0 (Custom Shaders) + Canvas 2D Text Overlay |
| **Layout** | In-browser GPU simulation | Precomputed offline layout (instant page load) |
| **Custom Styling** | Limited custom shader injection | Full custom node/edge vertex & fragment programs |
| **React Integration** | Standalone canvas wrapper | `@react-sigma/core` with idiomatic React hooks |
| **Interaction Lifecycle** | Good | Exceptional (hover states, node reducers, click events) |
| **Verdict** | Overkill for static layout | **Optimal for pixel-perfect UI, custom shaders, and reactivity** |

### 7.2 Main-Thread 60/120 FPS: GPU Uniform Edge Filtering
*Hazard:* Standard Sigma.js edge reducers execute JavaScript across 80,000 edges on every frame, freezing the main thread during slider dragging (dropping FPS to 5–10).

**Solution:** Custom WebGL Edge Program with GPU Uniform:
1. When generating WebGL vertex buffers, store normalized edge weight $w_{ab} \in [0, 1]$ directly in an attribute: `attribute float a_weight;`.
2. In the custom edge vertex shader:
   ```glsl
   attribute vec2 a_position;
   attribute float a_weight;
   uniform float u_minWeight; // Edge threshold from UI slider
   uniform mat3 u_matrix;

   void main() {
       if (a_weight < u_minWeight) {
           // Discard edge entirely outside clip space
           gl_Position = vec4(2.0, 2.0, 2.0, 0.0);
           return;
       }
       vec3 finalPos = u_matrix * vec3(a_position, 1.0);
       gl_Position = vec4(finalPos.xy, 0.0, 1.0);
   }
   ```
3. Dragging the UI slider updates `gl.uniform1f(u_minWeightLocation, sliderValue)` in **$O(1)$ time on the GPU**. Zero JavaScript graph iterations, zero buffer re-allocation, locked 60/120 FPS.

### 7.3 Neighborhood Illumination (Focus Mode)
When hovering over an artist node $X$:
1. **Nodes:** An in-memory `Set` of neighbors of $X$ is resolved in $O(1)$ via Graphology.
   - Selected node: Size scaled $\times 1.4$, pulsing halo glow.
   - Connected neighbors: Maintained at 100% opacity, labels forced visible.
   - Non-connected nodes: Dimmed to 12% opacity (`color: rgba(..., 0.12)`).
2. **Edges:**
   - Non-connected edges: Dynamically hidden via GPU uniform or fast bitmask.
   - Connected edges: Highlighted with a two-color gradient interpolating between the colors of node $X$ and neighbor $Y$, with thickness proportional to crossover.

### 7.4 Zoom-Dependent Level of Detail (LOD) Labels
To prevent label collisions while maintaining readability:
- **Global Zoom (Zoom < 1.5x):** Only Top 50 global superstars (Taylor Swift, Drake, Bad Bunny, The Weeknd) render visible labels.
- **Regional Zoom (Zoom 1.5x - 4.0x):** Major genre icons (Top 500 artists) display labels.
- **Local Zoom (Zoom > 4.0x):** Mid-tier and breakthrough artists display labels.
- **Deep Zoom (Zoom > 8.0x):** All 10,000 artist names are visible.
- **Always Active:** Any hovered node and its direct neighbors display labels regardless of zoom level.
